## Component Patterns & Conventions

### Component Structure
- **Functional components only** (no class components)
- **React hooks** for state management
- **React Router integration** for page navigation
- Export as default export

**Example pattern:**
```jsx
import { useState, useRef } from "react";
import { SomeIcon } from "lucide-react";

const MyComponent = ({ prop1, prop2 }) => {
  const [state, setState] = useState(null);
  const ref = useRef(null);

  const handleEvent = () => {
    // Logic here
  };

  return (
    <div className="tailwind-classes">
      {/* JSX */}
    </div>
  );
};

export default MyComponent;
```

### Styling Conventions

#### Tailwind CSS First
- Use Tailwind utility classes for all styling
- Avoid inline CSS when possible
- Custom colors defined in `tailwind.config.js`:
  - `custom_bg: "#7a919d"` — primary background color

#### CSS Variables (Custom Colors)
The project uses custom CSS variables for theme colors:
- `--color-bg` — background color (from Tailwind custom_bg)
- `--generic-2` — text color
- `--generic-8` — secondary text
- `--natural-4` — accent/hover state
- `--transparent-bg` — semi-transparent backgrounds

**Usage in components:**
```jsx
// Use CSS variables in className
<div className="bg-[rgb(var(--color-bg)/0.6)] text-[var(--generic-2)]">
  Content
</div>

// Or directly in style prop
<div style={{ color: 'var(--generic-2)' }}>
```

#### Custom Animations
- `pulse-once` — 0.4s scale animation (defined in Tailwind config)
- Used for interactive feedback
- Prefer Tailwind animations; only add custom ones to `tailwind.config.js`

#### Responsive Design
- Mobile-first approach
- Tailwind breakpoints: `md:`, `lg:`, `xl:`
- Example: `block lg:hidden` for mobile-only, `hidden lg:flex` for desktop-only

**Hero section pattern (mobile → desktop responsiveness):**
```jsx
<h1 className="text-5xl md:text-6xl lg:text-7xl">Large title</h1>
<div className="block lg:hidden">Mobile-only image</div>
<div className="hidden lg:flex">Desktop-only image</div>
```

## Data Management

### Project Data
- **File:** `src/projectData/projectData.js`
- **Format:** Array of project objects
- **Structure:** Each project has:
  - `id` — unique identifier (used in URL as `:projectId`)
  - `title` — project name
  - `description` — brief overview
  - `image` — cover image path (in `/public`)
  - `technologies` — tech stack string
  - `link` — internal route or external URL (determines Link vs <a> behavior)
  - Other relevant metadata

### ProjectCard Component
- Accepts `{ title, description, image, technologies, link }` props
- Distinguishes internal routes (`/projects/:id`) from external links (`http://...`)
- Uses `Link` for internal, `<a>` for external
- Hover effects with Tailwind transitions

## Firebase Integration

### Setup
- **Firebase Project:** `my-portfolio-cd16e`
- **Config:** `firebase.json` + `.firebaserc`
- **Deployment:** Functions run on Cloud Functions (runtime: nodejs20)
- **Linting:** predeploy hook runs `npm lint` in functions directory

### Cloud Functions
- **Location:** `functions/` directory
- **ChatBot Integration:** Cloud Function `askAnthropic` handles Claude API calls
  - **Endpoint (Local):** `http://localhost:5001/my-portfolio-cd16e/us-central1/askAnthropic`
  - **Endpoint (Production):** `https://askanthropic-hdk7woyz5a-uc.a.run.app`
  - **Method:** POST with `{ question: string }` body
  - **Response:** `{ reply: string }`

### ChatBot Component (`ChatBot.jsx`)
- Draggable widget (uses `react-draggable`)
- Local state management for messages
- Dynamic endpoint detection (localhost vs production)
- Renders markdown responses with `react-markdown`
- Shows loading state during API calls

## Common Patterns & Best Practices

### Adding a New Component
1. Create `.jsx` file in `src/components/`
2. Use functional component with hooks
3. Accept props as destructured object
4. Export as default
5. Import and use in pages or other components

**When to make a component:**
- Reusable across multiple pages
- Encapsulates complex logic
- Has its own state/effects

### Adding a New Page
1. Create `.jsx` file in `src/pages/`
2. Wrap in functional component
3. Add route to `App.jsx` under `<Route path="...">`
4. Use Tailwind for styling
5. Import other components as needed

**Example:**
```jsx
// pages/NewPage.jsx
import Hero from "../components/Hero";

const NewPage = () => {
  return (
    <div className="container mx-auto">
      <Hero />
      {/* More content */}
    </div>
  );
};

export default NewPage;
```

Then add to `App.jsx`:
```jsx
<Route path="/newpage" element={<NewPage />} />
```

### Handling Links
- **Internal navigation:** Use React Router `<Link to="/path">`
- **External links:** Use standard `<a href="..." target="_blank" rel="noopener noreferrer">`
- **Dynamic:** Use `useNavigate()` hook for programmatic navigation
